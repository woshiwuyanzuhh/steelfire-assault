# 50 关扩展计划

**目标**：把当前首关垂直切片扩展为至少 50 个可独立验收的横版动作射击关卡，同时完成 UI 安全区修正、右下角操作区重做、每 5 关一个 Boss、每关一个新玩法和一段可追踪剧情。

**工单规则**：`issues/level-01-*.md` 至 `issues/level-50-*.md` 每个只负责一个关卡的可演示纵向切片。关卡工单必须有自己的入口、资源清单、玩法判定、剧情节点、验收证据和回滚边界；不得把“50 关整体完成”写成单一工单来代替这些关卡工单。

**执行顺序**：

1. 先完成 `program-00-baseline.md`、`ui-01-safe-area.md`、`ui-02-control-deck.md`、`ui-03-regression.md`，冻结画布、安全区和操作区契约。
2. 按章节推进关卡：01–05、06–10、11–15、16–20、21–25、26–30、31–35、36–40、41–45、46–50。每章第 5 关是 Boss 关，必须在前 4 关的玩法和剧情证据齐备后进入实现。
3. 关卡实现沿用 Kotlin + Canvas、固定步长、状态快照/事件传递和本地 AssetRepository；禁止为了扩关引入未记录的引擎、联网服务或运行时 CDN。
4. 章节完成后运行对应工单的静态检查、APK 构建、真机路线录屏和离线网络检查，再进入下一章。

**共用验收底线**：每关必须支持冷启动后进入、移动/跳跃/下蹲/瞄准/射击/换武器/投掷、受击/死亡/检查点重试、离线运行、后台暂停、低性能模式和返回上一层；每个高伤害攻击至少提前 0.25 秒给出视觉与音频预警。Boss 关必须有至少 3 个可读阶段、弱点窗口、阶段 HUD 和结算返回。

**素材边界**：详细策略见 `ASSET_STRATEGY.md`。关卡只使用原创程序化图形、项目原创生成素材或已在 `ASSET_SOURCES.md` 记录的可再分发资源；不得把商业游戏的角色、地图、台词、字体、音频或可识别构图放入仓库。

**证据目录**：实现证据写入 `.scratch/50-level-expansion/audits/level-XX/`，至少包括截图/录屏索引、静态检查输出、APK 哈希、设备型号和已知限制。没有证据的“完成”只算开发中。
