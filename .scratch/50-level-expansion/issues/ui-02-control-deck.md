# UI-02：右下角操作区重做与视野遮挡修正

**目标**：把右下角操作区从大面积透明矩形改成分层、可折叠、可读且不遮挡关键战斗区域的操作甲板。

**Blocked by**：UI-01：横屏安全区与 UI 错位修正

**Status**：in_progress（代码实现与几何静态检查已通过；多指设备录屏待重新连接测试机）

## 问题定义

- 当前射击、瞄准、跳跃、蹲下、炸弹和换枪按钮占据过大的战斗视野，颜色与边框层次不足，长时间战斗会压住敌人、弹道和地形。
- 按钮在不同屏幕比例下仍需保持足够的触控面积，但可见装饰面积应降低；核心战斗信息必须优先显示。

## 设计方案

- 采用右下角半透明控制甲板：射击为主按钮，瞄准/跳跃为次按钮，炸弹/换枪为小型快捷键；按钮视觉尺寸与命中尺寸分离但不欺骗用户。
- 采用语义色 token、内描边、短标签和图标形状；按下、锁定、冷却、换弹、不可用状态必须有颜色、明度、动效和文字至少两种反馈。
- 增加“收起/展开”或半透明自动降噪策略：无输入时降低 alpha，敌人/弹道/弱点预警出现时自动让出高对比区域。
- 操作甲板不得覆盖玩家、敌人预警圈、Boss 弱点或弹道判定的关键可视区域；必要时根据安全矩形将甲板整体下移/向外收拢。
- 左侧摇杆与右侧甲板保持独立 pointerId；快速连点、两指/三指同时操作不能互相抢占。

## 验收标准

- [ ] 普通战斗截图中，玩家前方至少 35% 的可见横向空间不被操作按钮覆盖。
- [ ] 射击按钮、跳跃、蹲下、瞄准、炸弹和换枪在 2376×1080 及超宽横屏上仍 ≥72dp 可点。
- [ ] 按住射击连发、射击+移动、瞄准+跳跃、炸弹+移动的组合操作不丢动作、不重复扣弹、不崩溃。
- [ ] Boss 弱点窗口、敌人预警圈和关键弹道在按钮上层或按钮避让区域内完整可读。
- [ ] 低性能模式保留按钮状态、预警和准星，只减少装饰性脉冲/粒子。
